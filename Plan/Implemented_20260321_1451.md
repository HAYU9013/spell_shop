## 已完成系統詳細說明

### 全域定義（GameDefinitions.cs）

| Enum | 值 |
|---|---|
| EnvAttribute | Brightness, Moisture, Temperature |
| ExtremeEvent | None, Darkness, Flood, Overheat, Overcold |
| Rarity | Common, Rare, Legendary |
| RuneType | Cycle（循環）, Consumable（消耗） |
| RuneTag [Flags] | None, Water, Fire, Light, Dark, Wind, Neutral |
| CompareOperator | GreaterEqual, LessEqual, Equal, InRange |
| RequirementType | Absolute, RelativeChange, Stability, TagPreference |
| RelicPunishment | EnvironmentShock, ScoreReset, PlayerDeath |
| ScrollModifierType | DirectAdd, MultiplyAll, PositiveOnly, TagMultiply, Average, Invert |
| RewardType | RandomRune, RandomScroll, Relic, Score |

---

### 環境系統

- **EnvironmentData**：Brightness / Moisture / Temperature 各 0~20，Score 初始 30
- **ExtremeEventHandler**：觸碰邊界時一次性效果，大洪水支援連鎖（最多 10 次）
- **EnvironmentManager**：Singleton，`ApplyEffects` / `ForceSetValue` / `ModifyScore` / `SnapshotCurrent`
  - `RecordSnapshot()` — 每回合 Phase 5 結束後自動呼叫，推入歷史 deque
  - 歷史為 `LinkedList<EnvironmentData>`，頭 = 最新，尾 = 最舊，預設保留 20 筆
  - `GetHistoryAt(index)` — 0 = 本回合，1 = 上回合
  - 發出事件：`OnValueChanged` / `OnScoreChanged` / `OnExtremeEventTriggered` / `OnDarknessTriggered`

---

### 回合狀態機

**流程**（每回合）：
```
Phase 1  CustomerArrival    → CustomerManager.SpawnNextCustomer()
Phase 2  RelicTrigger       → RelicManager.TickAll()
Phase 3  DrawCards          → DeckManager.DiscardHandAndDraw()
Phase 4  PlayerAction       → 阻塞，等待 WorkbenchManager.Submit()
Phase 5  EnvironmentResolve → [ScrollProcessor TODO] + CustomerManager.UpdateCurrentTracking() + EnvironmentManager.RecordSnapshot()
Phase 6  CustomerJudge      → CustomerManager.CheckCurrentCustomer()
Phase 7  PatienceCheck      → CustomerManager.TickPatience()（已滿足則跳過）
Phase 8  RelicUpdate        → TurnManager.OnTurnEnd()
```

### Customer 系統

- **3 種需求類型**：

| 類型 | 判定方式 | requiredDelta 規則 |
|---|---|---|
| Absolute | 當前值符合條件 | — |
| RelativeChange | 顧客到來後累積變化達門檻 | 正值=增加達標；負值=減少達標 |
| Stability | 條件連續成立 N 回合 | — |

- 多條需求 = **AND 邏輯**（全部滿足才通過）
- **5 位預設顧客**（`SpellShop → Create Default Customers`）：

| 顧客 | 需求 | 條件 | 耐心 | 獎勵 |
|---|---|---|---|---|
| 落湯雞旅人 | Absolute | 溫度 >= 8 | 2 | +10 |
| 感冒農夫 | RelativeChange | 水分累積減少 >= 3 | 3 | +8 |
| 夜盲商人 | Absolute | 亮度 >= 10 | 1 | +20 |
| 冰魔法師 | Absolute × 2 | 溫度 <= 2 且 亮度 >= 5 | 4 | +15 |
| 養花老人 | Stability | 溫度 4~6 連續 1 回合 | 3 | +12 |

---

### Deck 系統

- **DeckManager**：抽牌堆 / 棄牌堆 / 手牌統一管理
  - 抽牌堆耗盡時自動洗入棄牌堆（Fisher-Yates 洗牌）
  - `DiscardHandAndDraw()` — Phase 3 一鍵棄手牌+抽新牌
  - `RemoveFromHand()` / `AddToHand()` — 工作台放入/取出
  - `DiscardRune()` / `ExhaustRune()` — 送出後依類型處理
  - `AddRune()` — 獎勵新增，進棄牌堆
  - 發出事件：`OnHandChanged` / `OnDeckChanged`

---

### Workbench 系統

- **WorkbenchManager**：
  - `SelectScroll()` — 設定卷軸，重置槽位（原有符文歸還手牌）
  - `PlaceRune()` — 放符文進下一個空槽，同步從 DeckManager 手牌移除
  - `RemoveRune(slotIndex)` — 取消，歸還手牌
  - `CanSubmit()` — 所有槽位填滿才回傳 true
  - `Submit()` — 建立 SubmitRecord → 處理符文（Cycle/Consumable）→ 呼叫 `TurnManager.PlayerSubmit()`
  - `LastSubmit` — Phase 5 取得本回合送出資料
  - `History` — `List<SubmitRecord>`，index 0 = 最新

## 未完成（待實作）

### 最優先：ScrollProcessor（Phase 5 缺口）

目前 Phase 5 只呼叫 `UpdateCurrentTracking()`，環境數值並未真正變動。
實作後才能完整跑通一局。

| 檔案 | 說明 |
|---|---|
| `ScrollProcessor.cs` | 依 `ScrollData.modifierType` 計算最終效果列表 |

**6 種修飾規則**：

| 規則 | 說明 |
|---|---|
| DirectAdd | 所有 RuneEffect 直接加總 |
| MultiplyAll | 加總後 × multiplier |
| PositiveOnly | 忽略 value < 0 的效果 |
| TagMultiply | 符合 tagFilter 的符文效果 × multiplier，其餘 DirectAdd |
| Average | 加總後 ÷ 符文數（float，最後取 int） |
| Invert | 所有 value 正負反轉 |
