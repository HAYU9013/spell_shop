# 咒語店 (Spell Shop) — 遊戲企劃文件

---

## 1. 遊戲概述

### 1.1 核心定位

| 項目     | 內容                             |
| -------- | -------------------------------- |
| 類型     | 策略 / 卡牌 / Roguelite          |
| 參考作品 | Slay the Spire、Potion Craft     |
| 核心樂趣 | 資源管理、組合運算、風險評估     |
| 目標玩家 | 喜歡思考深度與組合系統的策略玩家 |

### 1.2 一句話說明

> 玩家扮演咒語店老闆，透過組合符文與卷軸滿足顧客需求，同時在環境變數的壓力下維持遺物的平衡，在一波波顧客挑戰中撐過最長的回合數。

---

## 2. 世界觀與故事背景

玩家繼承了一間神秘的咒語商店。每天都有各式各樣的顧客帶著奇特的需求上門：旅人需要溫暖、農夫需要陽光、病人需要乾燥的空氣。店內擺放著古老的遺物，它們對環境極為敏感，若不加以照料將帶來災禍。

玩家的目標是盡可能維持店舖運作，累積業績，並在遺物的壓力與顧客的需求之間找到微妙的平衡。

## 3. 核心系統

### 3.1 環境系統

環境是整個遊戲的「共享狀態」，所有的符文、卷軸效果都作用於環境數值上。

#### 環境變數

| 變數               | 說明                           | 預設初始值 | 數值範圍 |
| ------------------ | ------------------------------ | ---------- | -------- |
| 亮度 (Brightness)  | 光線強度，影響視野與植物類顧客 | 5          | 0 ~ 20   |
| 水分 (Moisture)    | 環境溼度，影響冷熱感受         | 5          | 0 ~ 20   |
| 溫度 (Temperature) | 環境溫度，影響舒適度           | 5          | 0 ~ 20   |
| 業績 (Score)       | 累積分數，作為玩家成績指標     | 0          | 0 ~ ∞    |

- 數值**超出範圍**時觸發極端效果（例如亮度=0 → 進入黑暗狀態；溫度=20 → 燃燒狀態）
- 業績僅累加，不受環境直接影響

#### 極端狀態（草案）

| 狀態   | 觸發條件  | 效果                                              |
| ------ | --------- | ------------------------------------------------- |
| 黑暗   | 亮度 = 0  | 每回合額外亮度 -1（直至補回），遺物不滿意計數加速 |
| 大洪水 | 水分 = 20 | 每回合水分 +1 自動疊加，直至介入                  |
| 高溫   | 溫度 = 20 | 部分符文效果翻倍但玩家受到持續損傷                |

---

### 3.2 符文系統

符文是最基本的效果單位，代表單一的環境修改操作。

#### 符文結構

```
符文 {
  名稱
  效果列表（例：水分 +2、亮度 -1）
  稀有度（普通 / 稀有 / 傳說）
  標籤（水系 / 火系 / 光系 / 暗系 / 中性 ...）
}
```

#### 範例符文

| 符文名稱 | 效果                      | 稀有度 | 標籤       |
| -------- | ------------------------- | ------ | ---------- |
| 水珠     | 水分 +2                   | 普通   | 水系       |
| 小燭     | 亮度 +1、溫度 +1          | 普通   | 火系、光系 |
| 寒冰     | 溫度 -3、水分 +1          | 稀有   | 水系       |
| 太陽核   | 亮度 +5、溫度 +3、水分 -2 | 傳說   | 火系、光系 |
| 黑霧     | 亮度 -2、水分 +1          | 普通   | 暗系       |
| 蒸氣     | 溫度 -1、水分 -1、亮度 +1 | 普通   | 中性       |

---

### 3.3 卷軸系統

卷軸是符文的容器與放大器，決定符文效果如何被計算。

#### 卷軸結構

```
卷軸 {
  名稱
  符文槽數（必須放滿才能送出）
  修飾規則（如：所有效果 ×2、只取最大效果）
  標籤限制（如：只能放水系符文）
  稀有度
}
```

#### 範例卷軸

| 卷軸名稱 | 槽數 | 修飾規則             | 限制         |
| -------- | ---- | -------------------- | ------------ |
| 基礎卷軸 | 2    | 效果直接疊加         | 無           |
| 放大卷軸 | 3    | 所有效果 ×2          | 無           |
| 純化卷軸 | 2    | 只計算正值效果       | 無           |
| 水系卷軸 | 3    | 水系效果 ×3          | 僅限水系符文 |
| 平衡卷軸 | 4    | 所有效果取平均後套用 | 無           |
| 逆轉卷軸 | 2    | 所有效果正負反轉     | 無           |

#### 卷軸使用流程

```
1. 玩家選擇一個卷軸
2. 從手牌中拖入符文，直到槽位填滿
3. 預覽最終效果
4. 按下「送出」確認
5. 環境數值更新
```

> **設計要點**：必須「放滿」才能送出，強迫玩家做出取捨，不能只放有利的符文。

### 3.4 顧客系統

顧客是每回合的主要目標，提供資源收益的來源。

#### 顧客結構

```
顧客 {
  名稱 / 外觀
  需求（目標環境條件，例：溫度 >= 8）
  等待耐心（可容忍未被滿足的回合數）
  獎勵（符文 / 卷軸 / 業績加成）
  特殊對話
}
```

#### 需求類型

| 需求類型     | 範例                           |
| ------------ | ------------------------------ |
| 絕對值條件   | 溫度 >= 8                      |
| 相對變化條件 | 本回合水分減少 >= 3            |
| 複合條件     | 亮度 >= 6 且 溫度 <= 4         |
| 環境穩定條件 | 連續 2 回合溫度維持在 4~6 之間 |

#### 顧客範例

| 顧客       | 需求                   | 耐心          | 獎勵           |
| ---------- | ---------------------- | ------------- | -------------- |
| 落湯雞旅人 | 溫度 >= 8              | 2回合         | 卷軸：放大卷軸 |
| 感冒農夫   | 水分 <= 3              | 3回合         | 符文×3（隨機） |
| 夜盲商人   | 亮度 >= 10             | 1回合（急客） | 業績 +20       |
| 冰魔法師   | 溫度 <= 2 且 亮度 >= 5 | 4回合         | 稀有符文×2     |

---

### 3.5 遺物系統

遺物是持續存在的壓力來源，帶來風險與獎勵的雙面性。

#### 遺物結構

```
遺物 {
  名稱
  滿意條件（環境條件）
  滿意效果（每回合正向效果）
  不滿意效果（副作用）
  不滿意容忍上限（連續不滿意 N 回合後觸發懲罰）
  當前不滿意計數
}
```

#### 遺物範例

| 遺物     | 滿意條件            | 滿意效果             | 不滿意效果        | 觸發懲罰（達上限）    |
| -------- | ------------------- | -------------------- | ----------------- | --------------------- |
| 日晷     | 亮度 >= 7           | 每回合亮度 +1        | 每回合亮度 -1     | 連續4回合後：亮度 -5  |
| 苔蘚石   | 水分 4~8 之間       | 每回合業績 +5        | 無額外效果        | 連續3回合後：水分 +5  |
| 骸骨燭台 | 溫度 <= 3           | 每回合額外抽一張符文 | 溫度 +2（每回合） | 連續2回合後：玩家死亡 |
| 風鈴草   | 三項環境值均在 3~10 | 每回合所有正效果 +1  | 下回合隨機一項 -3 | 連續5回合後：業績清零 |

#### 遺物互動設計原則

- 遺物的滿意條件應與顧客需求**有時衝突**，製造策略張力
- 每局遊戲隨機組合 1~3 個遺物，增加變數
- 骸骨燭台這類「高風險高報酬」的遺物讓玩家自行評估是否接受

## 4. 遊戲循環詳解

```
┌──────────────────────────────────────────────┐
│                 回合開始                        │
│                                              │
│  1. 新顧客到來（顯示需求與耐心倒數）               │
│                  ↓                           │
│  2. 遺物效果觸發（滿意→獎勵 / 不滿意→副作用）      │
│                  ↓                           │
│  3. 玩家手牌補充（從牌庫抽取符文）                 │
│                  ↓                           │
│  4. 玩家行動階段：選卷軸 → 放符文 → 送出           │
│                  ↓                           │
│  5. 環境數值結算（計算卷軸效果，更新環境）           │
│                  ↓                           │
│  6. 顧客需求判定                               │
│     ├── 滿足 → 給予獎勵，業績 +N，顧客離開         │
│     └── 未滿足 → 顧客耐心 -1                    │
│                  ↓                           │
│  7. 顧客耐心判定                               │
│     ├── 耐心 > 0 → 顧客繼續等待（進入下一回合）      │
│     └── 耐心 = 0 → 顧客憤怒離開，業績 -N           │
│                  ↓                           │
│  8. 遺物不滿意計數更新                          │
│     └── 達到上限 → 觸發終極懲罰                  │
│                  ↓                           │
│            回合結束，進入下一回合                  │
└──────────────────────────────────────────────┘
```

## 5. 玩家資源管理

### 5.1 手牌系統

- 玩家擁有一副「符文牌庫」，每回合開始抽取固定數量（預設 5 張）
- 使用過的符文進入棄牌堆，牌庫抽完後洗牌重來
- 顧客給予的符文直接加入牌庫

### 5.2 卷軸管理

- 為消耗品，用後移除
- 顧客給予的卷軸直接加入卷軸池

### 5.3 牌庫構築

- 玩家在遊戲過程中逐步構建牌庫（類似 Slay the Spire 的牌庫構築）
- 可在特定時機移除不需要的符文（減少雜訊）
- 稀有符文帶來強力但侷限性高的效果

---

## 6. 勝負判定

### 6.1 失敗條件

- 遺物的不滿意計數達到觸發懲罰上限，且懲罰為「玩家死亡」
- 業績降至 0 以下（破產）
- 特定遺物的即死效果

### 6.2 勝利條件（建議）

- **無限模式**：盡可能存活更多回合，以最終業績作為排行榜分數
- **挑戰模式**：完成指定回合數（例如接待 30 位顧客）並達到目標業績

---

## 7. 進程與隨機性

### 7.1 Roguelite 元素

| 元素         | 說明                                       |
| ------------ | ------------------------------------------ |
| 隨機符文獎勵 | 顧客給予的符文從池中隨機選取               |
| 隨機顧客序列 | 每局顧客順序不同，部分特殊顧客機率出現     |
| 隨機遺物組合 | 每局隨機抽取 N 個遺物，帶來不同的環境壓力  |
| 隨機事件     | 特殊回合可能出現「環境異變」或「神秘訪客」 |

### 7.2 難度曲線

- 早期顧客需求簡單（單一條件、寬鬆範圍）
- 中期開始出現複合條件顧客與要求苛刻的遺物
- 後期顧客耐心縮短，且遺物的不滿意閾值降低

1. 玩家點擊卷軸選擇下拉選單，預覽各卷軸的槽數與規則

4. 確認後點擊「送出」，播放動畫效果，環境數值更新

## 10. 設計哲學與注意事項

1. **強迫取捨**：卷軸必須放滿的設計讓每次行動都有副作用，避免「完美解」
2. **多目標競爭**：顧客需求 vs 遺物條件 vs 環境極端狀態，三方壓力讓每回合都有思考空間
3. **可預測性**：環境數值透明公開，玩家的失敗必須是因為決策失誤而非資訊不足
4. **驚喜感**：Roguelite 的隨機遺物與顧客組合讓每局體驗不同
5. **短局設計**：單局時間控制在 15~30 分鐘，適合反覆遊玩
